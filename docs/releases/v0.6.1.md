# Coworker v0.6.1

Give each coworker their own Telegram and Discord connections, and manage them directly from coworker settings or the global Integrations page.

## Messaging for each coworker

- Each coworker can have one active Telegram bot and one active Discord bot at the same time. Other coworkers can connect their own bots independently.
- Configure, pair, edit, unpair, disconnect, and reconnect bots from **coworker settings → Messaging connections** or **Settings → Integrations**. Both views manage the same connections.
- Each Telegram bot pairs with one private chat; each Discord bot pairs with one server channel. Topics and threads keep separate conversations.
- Each connection has its own credentials, pairing, transport progress, and runtime. Errors and reconnects stay scoped to the affected bot.
- Duplicate bot identities and occupied coworker/platform slots are rejected before changing credentials or moving a connection.

## Conversation sync and delivery

- Conversations started through Telegram or Discord appear on desktop and sync replies through their originating bot, including replies written from desktop.
- New desktop conversations stay local. They no longer automatically create Telegram topics or Discord threads; explicitly request messaging delivery when needed.
- Messaging tools resolve the current coworker's paired connection and reject another coworker's connection. Approvals retain the chosen bot, destination, and thread, and fail if that destination changes before delivery.
- Concurrent attachments and Discord thread creation preserve independent files and conversation mappings.

## Upgrading and CLI

- Existing integration IDs, credentials, and pairings are preserved. Connections start fresh conversations after the routing upgrade; existing desktop and messaging history remains available.
- Moving a bot to another coworker keeps its pairing and starts fresh conversations, leaving old history with the previous coworker.
- If an older profile has several active connections for the same coworker and platform, those conflicting connections are paused while their credentials, pairings, and history are preserved. Reconnect the desired bot or move it to a coworker with a free slot.
- CLI status lists connections with their integration IDs. `configure` without `--integration-id` creates a connection in a free slot; provide `--integration-id` to edit or move an existing connection. `unpair` and `disconnect` require `--integration-id`.
- Unpairing keeps the platform slot occupied. Disconnecting frees it and removes that connection's credential, while preserving configured approval policies.
